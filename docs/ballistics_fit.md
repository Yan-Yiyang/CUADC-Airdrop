# 投放记录 + 弹道参数反演

本文档说明：投放记录（位置/速度/姿态/风）与实测落点的配对方式、反演实际可识别的参数范围、
必须拒绝给出结论的情形、工具的使用方法。做投放试验、改 `ballistics/fit.py` 或调
`BallisticsConfig` 之前请先阅读本文档。
**本文件是该项目对应模块的专题笔记（实测口径与工具用法）。**

---

- **投放记录 + 弹道参数反演（已实现）**（投弹时记录位置/速度/姿态，再用多次投放的投放点
  与**实测落点**反演弹道参数）。36 个离线用例（`tests/test_fit.py`）。要点与易错点：
  * **密度基准取记录的原点海拔**（`ground_altitude_m = origin.alt_m − ground_z`；关闭 `air_density_isa`
    时也在投放海拔算一次常密度，见 [`docs/handbook.md`](handbook.md) §3.7.1）。同一站点自洽；
    **记录缺原点会退回海平面基准，并在 `FitResult.warnings` 里告警**。改过密度基准、或把参数
    换到别的站点/海拔使用前，先重跑一次反演——`Cd` 会按密度差等比变化（`κ = Cd·A/m` 的相对关系不变）。
  * **数据两边**：`DropRecord` 记投放瞬间的**位置/速度/姿态（欧拉角+四元数）/风/离地高度/
    NED 原点/目标点/判据前推位置与预测落点**；实测落点由**测量文件**给（`impacts.jsonl`/
    `.csv`，经纬度或 NED；模板可生成），按**该条记录自己的原点**换算。
  * **`ReleaseDecision.delay_s` 是必需的**：记录要写**判据当时真正用的**前推量，不能读 runner
    自己的 config（编写用例时曾遇到：judge 0.08、runner config 0.0），差一个延迟会**全算到 Cd 上**。
  * **反演的本质是"参数能不能辨识"，不是"残差能不能压小"**（`ballistics/fit.py`）：
    1. **质量不反演——它是称出来的**：`FIT_PARAMETERS` 里没有 `mass_kg`。**识别到的只有一个
       数 κ = Cd·A/m**（`drag_k_per_m`）；给定实测质量才有 `Cd·A = κ·m`。实测：质量
       0.365→0.500 重拟合，**Cd 与 Cd·A 同步变 1.37 倍、κ 不变**——所以质量必须实测；换配重
       按 `κ' = Cd·A/m'` 重算，不必重做试验（工具里是 `MEASURED_MASS_KG`）。
    2. **Cd 与迎风面积只能固定一个**（只以乘积可辨识）⇒ 两个都拟合**直接拒绝**。
    3. **释放延迟与阻力沿航迹方向高度相关**：同高同速 4 投条件数实测 **1.06e10**（收敛到完全
       错误的 `Cd=0.555 / δ=0.164`）→ 超阈值拒绝；速度/高度拉开后条件数 17.5、两参数都回到
       1e-3 以内。⚠ **有风反而容易分离**（同地速在不同航向下空速不同）——"分不开"的用例
       必须用**零风**。
    4. **常数偏差（测量点/目标点坐标错）吸收不掉**：`bias_north/east_m` 单列并提示先核对坐标。
  * σ/相关性与条件数用**自算中心差分雅可比 + SVD**（`inv(JᵗJ)` 近奇异会返回不可用的结果），
    自由度 ≤ 0 即说明"σ 无从谈起"；**留一交叉验证默认开**——残差偏小最容易造成误判。
  * **正演初始条件只有两个修正项**（`release_conditions`）：一阶前推 `p + v·δ` 与**机体系挂点
    偏移**（经记录里的姿态转 NED）。**姿态在弹道里的用途只有这一处**。
  * `tools/fit_ballistics.py`：对照表（判据预测/反演后/实测，含沿航迹·垂直航迹分解）+
    JSON 报告 + 可粘回的 `BallisticsConfig(...)`。⚠ **本地没有真实投放数据**（收回真值
    全是合成的，~1e-6）。
