# 仿真世界与任务接入

世界、机型、相机及启动脚本位于[airdrop-sim](../vendor/airdrop-sim/README.md)，布局、规则与坐标说明见工具仓的[世界说明](../vendor/airdrop-sim/docs/simulation_world.md)。

工具生成世界与相机manifest；主仓使用`python -m airdrop.run mission --mode sitl --manifest <文件>`接入任务。生成器不运行识别或投放控制，主仓不修改PX4/QGC参考源码。初始化方式见[工具仓库](tool_repositories.md)，输入输出见[契约](tool_contracts.md)。

## 参数与生命周期

更换机型时回读`MIS_TKO_LAND_REQ`、`FW_LND_ANG`、`FW_LND_USETER`，降落预检必须使用实际配置的进场角。仅在明确隔离的上传检查中按需调整任务起降项要求，不将测试参数直接用于真机。

固定翼 SITL 起飞使用只含 `NAV_TAKEOFF` 的任务。上传/下载一致性检查遵循飞控实际存储语义：当前起飞项将 `param1`、`param2`、`param3` 置零，避免把飞控归一化回读误判为任务不一致。该任务入口仅用于已隔离的仿真，不覆盖操作手任务。

固定翼航线必须满足转弯半径、相机覆盖与降落剖面约束。改变seed或世界原点后重规划对应航线；操作手`.plan`文件属于本地输入，不随仓库提供。

只停止本次创建的实例，不全局关闭WSL。资源监测按当前操作手约定配置，区分启动峰值与持续繁忙；仿真时间与墙钟时间可能不同，性能与业务时间需要分别记录。

项目 Python、遥测、识别、回放、测试与 QGC 在 Windows 运行；WSL 只运行仿真与仿真配置。旧 GZBridge 的磁力计坐标/单位兼容可在独立运行目录采用工具仓 `airdrop_sim/assets/compat/` 中的适配插件；须配套启用 Gazebo Tesla/ENU 模式和换算传感器噪声，不能单独交换体轴。脚本检查指定 PX4 源码；运行二进制须与源码匹配，拒绝二次补偿；具体前置条件见该目录 README。

GNSS 延时先用原生飞控时钟核对传感器与真值，再在干净参数实例中做参数对照。`PX4_PARAM_EKF2_GPS_DELAY` 仅用于配置相应仿真，不能直接套用真机。任何位置估计时序变化后都要重新标定图传链路延时。

`TelemetryConfig.source_time_alignment=True` 可启用位置/四元数字段源时标内插，默认关闭。它通过 MAVSDK MavlinkDirect 保留位置 boot 时标，以四元数接收时轴作局部映射，适应仿真速率变化；缺源数据、断流或时钟重启时拒绝跨段内插。此映射仍含传输抖动，不是精确曝光同步。真实相机与仿真均继续使用 Windows 收帧时间减 `VideoConfig.telemetry_lag`，无需准确逐帧拍摄时间，也未启用仿真专用曝光时标通道。改变该开关或仿真传感器配置后，用独立航次重新标定；旧记录按其配置快照复算。

时序验收以实际读取数据与原生仿真数据的一致性为依据：按各字段源时标逐条对应位置、速度和四元数，报告值差、匹配覆盖、源日志采样分辨率，以及源时钟到 Windows 接收时轴的局部映射与抖动。原生日志缺少对应采样时须单独列出；限定间隔的插值核验不能写成逐条精确匹配。每轮独立保存映射与参数，不套用其它飞行轮次的常数。没有共同外部时钟和相机曝光时标时，不能仅凭这些数据证明绝对单向网络时延或真实拍摄延迟。

精度指标、聚类与同编号均值、姿态误差隔离及链路带宽检查见[定位诊断](simulation_world.md#定位误差与时间对齐诊断)。GNSS 对照试验与视频延迟补偿分别处理；不能把单轮有效补偿量推广为所有仿真或真机的固定值。

## 验收范围

只读任务观察需要覆盖初次下载、替换、同项数替换、断连与进度重建；观察器不得代替操作手上传、清空或启动任务。相机接入、识别定位、模拟投放和降落需要在同一实例里联合验收。

合成测试、历史固定航迹回放和Gazebo分别覆盖不同条件。当前版本的实际相机、现场链路延迟与真实挂架仍需独立验证；不能把图像可解码或显卡可见当作完整任务通过。

## 定位误差与时间对齐诊断

诊断同时报告观测点、目标中心和任务选择结果；三者不能互相代替。视频发布与收尾方法见[性能度量](performance.md)，仿真配置和钟域边界见[仿真说明](simulation_world.md)。

### 误差指标和绘图

单次观测的水平误差为 `sqrt((north - north_true)^2 + (east - east_true)^2)`；全量点的 RMSE 为这些误差平方的均值再开方。同时报告点数、中位数、P90、最大值和门限内比例，不能只报告最优点或最终中心。

目标中心误差使用融合后坐标计算，与全量观测点 RMSE 分开。任务最终选中一个编号时，还须列出其它编号的覆盖、同编号多簇及选择规则。最终中心通过门限，不表示所有散点都在门限内。

底图使用实际场景的世界坐标；飞控 NED 原点与场景原点不同时，先经共同地理原点转换，再绘制场景 ENU。真值、观测点和中心必须在同一坐标系内。参考误差圈只作为图例，不视为场地标线。

离线复算复用实际投影口径：四元数/欧拉角的选用、相机安装姿态、地面高度面、内参与去畸变标记保持一致。已去畸变像素不能再次去畸变；缺少实际运行字段时，明确标为诊断复算，不能声称逐位还原在线点。

### 聚类与同编号均值

两种方法必须使用同一批坐标、同一真值及预先冻结的参数。分别列出全部同编号点均值、生产聚类所选簇的均值、各自成员数及未参与点。多簇按生产规则选择，不能看过真值再挑最准确的簇。

DBSCAN 的改善来自空间密度筛选改变了参与均值的点集，并不修正每个点。共同偏移不会自动消失；密集的偏差点也可能形成错误簇。单架次的中心改善不能证明聚类普遍优于直接平均。

无编号观测与已编号观测在生产聚类中的处理也须保持原样。按编号直接平均无法自然使用无编号点，比较时应说明两种方法的实际点集差异。

### 姿态与上游估计

先在同一源时刻比较飞控估计姿态与仿真真值，再分析偏差和滚转、俯仰、航向、观测距离及通过方向的关系。大滚转本身不足以解释异常；低滚转也可能伴随较大的航向误差。

可固定检测像素，分别只替换位置、航向或完整姿态，以隔离误差来源。真值替换只用于诊断，不能进入在线算法或算作部署后的验收结果。全量单点 RMSE 降低也不保证最终中心改善：投影变化会改变聚类成员和选簇结果。

不直接按姿态幅度剔点。任何质量门槛都要同时验证点数、编号覆盖、目标选择与最终中心，防止丢失一个编号后改变任务选择。航迹角受风、侧滑和转弯影响，不能直接替代机体航向。

仿真航向异常要检查磁场单位、机体和世界坐标约定、噪声单位、估计器创新及重置。单个 yaw-aligned 标志不证明估计质量；重复的航向重置也不能简单解释为初始收敛。干净实例和继承校准的实例分开比较，避免自动磁校准污染 A/B 初始条件。

### 源时标、接收时间与延迟

总体快照时间可被任意遥测字段更新，不代表位置、速度和姿态同时采样。逐字段记录源时标与本地接收时刻；区分源采样差、接收后持有年龄、仿真速率和系统 UTC 差。这些量不能直接相加。

时序核验优先在同一个飞控原生时钟内对照传感器和仿真真值，再用位置/速度或四元数指纹对应业务记录。源日志缺采样时，将精确匹配与有限间隔插值分别报告。接收时间映射和 TIMESYNC 均不能单独证明相机真实曝光时间或绝对单向网络延迟。

每轮仿真的实际延迟和参数独立核对。用于验证识别、投影和融合逻辑的默认精度分析应排除延迟标定失配：补偿与本轮实际链路一致；只有显式研究失配时才把不同补偿设定作为比较变量。该分析口径不表示现有工具已经自动测得真实曝光延迟，也不把配置值或最小落点拟合值称为实测值。落点反推可作为诊断保留，不引入固定的跨轮常数或复杂的仿真专用估计流程。

GNSS 延时属于飞控内部传感器时序，与视频补偿分开验证。桥接样本没有对应排队延迟时，沿用另一传感器的估计器延时参数可能导致位置时序偏差。修改传感器或源时间配置后重新核对，不能在业务端加反向偏移掩盖上游配置问题。

### 通信与验收边界

列出实际订阅的消息和请求频率，再测视频、QGC、任务传输同时运行时的频率、吞吐、抖动和丢包。欧拉角与四元数是不同消息，均需计入带宽；速率设置成功不证明共享链路能维持该频率。新增源时标通路时说明连接复用和额外请求，不以本地内插掩盖上游丢包。

仿真和配置在 WSL，项目遥测、识别、分析、测试与 QGC 在 Windows。离线数值一致、固定轨迹回放、独立新航次与真实设备验收分别记录。原始验证数据退役后，保留的方法文档不替代可重放证据；新的结论需要重新采集和冻结输入、参数及判据。
