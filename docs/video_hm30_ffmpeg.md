# HM30 图传与 FFmpeg 后端

主仓使用FFmpeg子进程接收和解码视频。图像数据通过固定尺寸rawvideo进入采集线程，逐帧sink写入对齐缓冲；`read()`/`latest()`只用于允许覆盖旧帧的预览。

## 后端与停止

`VideoCapture.read()`可能阻塞在不可中断的原生调用中。独立FFmpeg进程使停止时能关闭管道、终止并回收进程，避免把视频读取生命周期绑定在工作线程退出上。是否存在FFmpeg插件、支持哪些选项取决于实际OpenCV构建，不能通过某个二进制中没有字符串就断定接口被删除。

视频输入地址需要显式配置，程序不探测相机地址。网络协议和本地文件的选项不同：UDP读取超时使用所支持的协议层参数，本地文件或SDP输入不应收到不支持的`-timeout`。调整选项后应实际验证无帧、断流和停止行为。

## 时延、积压与丢失

- `capture_timestamp`由接收时间减去标定的`telemetry_lag`得到，不是相机硬件采样戳。更换相机、传输或解码参数后重新标定。
- UDP数据可能在套接字或上游丢失，这不一定反映在应用的`stats.dropped`中；格式探测也可能消耗尚未输出的数据。减小探测范围可能降低启动等待，也可能导致探测失败。
- 慢sink会造成反压，解码器邮箱统计不能证明上游没有丢包。检测和录制应从对齐缓冲消费，预览允许单帧覆盖。
- 跨帧保存采集的ndarray必须复制；不能持有会被复用的底层缓冲视图。

排查时记录输入帧编号、接收/处理时间、缓冲积压和进程状态，并在同一负载下比较。QGC发布端RTP时钟与窗口录屏诊断见[性能说明](performance.md)，配置及文件字段见[手册](handbook.md)。
