# 开发与发布

`main` 保存已整合的工作；功能在短期分支开发，经相应检查后合入。发布通过版本标签标记。

## 提交与文档

一个提交描述一个可解释的功能、修复或接口调整，连同必要测试和文档一起提交。合并同一工作中的格式修正、拼写和即时补丁；保留能解释功能演进、异常语义和接口边界的变更。尚未验收的算法放在独立分支。

README提供使用入口，手册解释参数、数据与流程，专题文档保存可复用的方法和约束，AGENTS.md提供AI执行入口。设备问题应写成适用条件、复现步骤、现象和验证边界；不把某台电脑的速度、路径或一次成功当作通用保证。

## 本地资料

本地笔记和恢复资料放在被忽略的`.local/`；航线、飞行记录、模型权重、虚拟环境和编辑器配置遵循`.gitignore`。不要使用`git add -f`把这些资料加入提交。

提交前检查`git diff --cached`与`git status --short`，确认没有真实素材、设备标识、凭证或依赖个人目录的路径。`.gitignore`只约束未跟踪文件，无法清除已经提交的内容。公开示例使用占位路径和可配置输入；署名与许可证声明应保留。

## 验证与发布

按影响范围执行AGENTS.md列出的检查，至少说明运行了哪些测试、哪些设备或平台条件没有验证。跨仓变更固定两个工具子模块的提交，分别验证工具本身和主仓数据契约。

发布时统一更新`pyproject.toml`、`airdrop/__init__.py`、`uv.lock`中的本项目版本、README和发布说明。检查干净克隆能运行帮助及离线测试，再在已验证提交上创建标签。升级不自动上传或启动操作手任务。
