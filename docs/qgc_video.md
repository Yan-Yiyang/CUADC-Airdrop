# QGC 合成视频

主仓将任务状态、识别画面与投放信息合成为 1760×990（16:9）视频，通过本地或指定主机的 UDP 发布给 QGroundControl。该功能默认关闭，使用已有 ffmpeg，不要求安装新的模型或工具子仓。

## 使用

```bash
# 合成测试画面：不连接飞控，不加载识别模型
python -m airdrop.run qgc-video-test --port 5602 --seconds 10
# 在线任务与离线回放均可启用
python -m airdrop.run mission --mode real --qgc-video
python -m airdrop.run mission --mode sitl --qgc-video
python -m airdrop.run replay --flight flights/<架次> --qgc-video
```

QGC 的视频源选择 UDP H.264，接收端口设为 5602。默认 `rtp` 传输使用 RTP/H.264，编码器定期发送关键帧和参数集，支持接收端晚加入；选择 `mpegts` 时，QGC 应改用 MPEG-TS 视频源。QGC 的 `udp://` H.264 源需要 RTP 封装，不能直接接收裸 Annex B 字节。

`--qgc-host`、`--qgc-port`、`--qgc-transport` 覆盖发布目标。默认发送至 `127.0.0.1:5602`；RTP 同时使用下一端口作为 RTCP。SITL 相机输入通常占用 5600/5601，输出端口对必须与输入分开。显式冲突在连接或创建运行产物前拒绝。远程接收时还需按实际网络配置允许对应 UDP 端口。

开启显示仍要求 `--capture`。关闭识别时可以显示原始实时视频和任务状态，不加载相机标定、检测或 OCR；缺少有效几何时不绘空间标记。真实任务仍须提供场地航线与其它必要参数，显示开关不替代任务配置，也不启用真实挂架动作。

`qgc-video-test` 的默认预览采用任务二 A 区：四座随机朝向的五边形天井，其中三个放白底黑字双数字板（94、12、56），中位目标为 56。形状、板尺寸和选靶口径依据 [2026 规则第 3.3、5.8 节及图 4](https://www.cuadc.cn/upload/file/20260420/6391229384941808466022079.pdf)，位置沿用入库 seed=0 场景。画面按 1280×720、1.74rad 水平视场和 15m 下视高度投影，并标注合成演示与比例尺；场地纹理和阴影是示意，不是实拍。视场外靶标只保留先前画面的真实对应裁剪，不把全部场地硬塞进同一帧；不在地面绘制计分示意圈。

## 画面与时间口径

顶部 130 像素显示阶段色块与独立计时卡：侦查展示当前航线进度与阶段用时，盘旋展示距超时与预计处理时间，投放阶段展示命令状态与时刻；中部为 1280×720 视频区域和 480×720 目标面板；底部 140 像素分为处理进度、发布与链路、航线与投放三列。不同尺寸的输入等比缩放留边，所有框与标记共用相同的缩放和偏移。

已完成阶段只按实际迁移记录着色；参数跳过的投放或降落阶段不标成已完成，中止也不推定已经返航降落。

画面标签使用中文，由 Pillow 与系统中文字体绘制，支持微软雅黑、黑体、Noto Sans CJK 或文泉驿字体。字体和字号缓存复用，每帧集中绘制文字；不会将汉字直接交给不支持中文的 OpenCV 内置字体。缺少支持的中文字体时记录显示错误。

| 阶段 | 画面来源与叠加 |
| --- | --- |
| RECON | 最近完成检测的历史帧及其自身检测框，显示独立观测云 |
| HOLD_PROCESS | 积压未排空时继续跟随处理帧；处理完成后切到实时画面，保留历史观测散点，不迁移旧检测框 |
| OVERFLY / LAND | 实时画面，只画选定目标、已有判据事件中的预测落点及方向提示 |
| 无识别 / 无处理帧 | 实时画面；不把旧检测框叠到新图上 |

每个处理帧快照携带缓冲帧号、接收/拍摄/处理时间、同帧位姿、实际内参和去畸变标记。缓冲帧号与视频源帧号是两个编号空间；实时位姿按拍摄时间对齐，不按帧号猜测对应关系。零检测帧也更新画面。晚到 OCR 只回填匹配的历史帧；历史已淘汰时显示缺图状态，不从当前画面同一位置冒认截图。

当前检测去畸变保持原标定内参 K 与原始尺寸。历史去畸变图上的投影关闭畸变；原始实时图上的投影使用标定畸变。缺失位姿、标定尺寸不符、非有限数据或相机后方点不绘几何位置。出界的前方目标保留方向，使用边缘提示。`ned_to_pixel` 与现有 `pixel_to_ned` 共用 NED、机体 FRD、相机 optical 和非零杆臂约定，返回 `ProjectedPoint` 说明可投影性。

编号面板横排展示最近三个不同编号的截图，下方按观测频次排序展示 NED 与 WGS84 坐标，同频次按编号升序。编号、缩略图与观测散点共用确定的颜色。坐标是显示窗口内观测的均值，任务选定目标仍以业务聚类与 `drop_plan` 为准。面板与观测云只用于显示，不向业务统计重复添加观测。

预测落点来自已经发生的 `drop_check` / `release` 事件。投放提示区分发送中、指令已发出、失败和结果未知；模拟动作另行标明。`drop_released` 表示控制器成功返回后业务已记录投放，不代表已取得挂架或载荷分离的物理反馈。判据触发不能单独显示为指令已发出。

选定目标使用中心留空的绿色准星，预测落点使用红色圆环与中心点，并提供文字图例；历史观测点半透明显示，避免遮住原始数字板。缩略图等比显示，保持实体比例。落点误差与预计飞行时间来自同一判据事件。出界提示保持在视频区域内，不覆盖面板或状态栏。预计处理时间只用于显示，缺少速度样本时显示未知，不改变任务超时和完成判定。

回放保留素材的原始时间轴，明确标注离线回放，不把素材距今天的时间显示为采集或遥测延迟，也不合成历史任务阶段。缩略图年龄按已播放素材时间计算。在线的发布延迟统计表示拍摄至写入编码管道；回放表示本次提交至写入编码管道，均不等于 QGC 接收窗口的端到端延迟。

## 隔离与收尾

发布器不调用目标源的 `pump()` / `result()`，不调用投放判据 `update()`，也不清空主缓冲或改变识别截止游标。识别结果和飞行记录保持原消费路径；只有显示邮箱允许覆盖旧帧，历史图像和观测云均有容量上限。显示切换不会停止后续飞行记录。

图像合成和编码运行在独立线程。ffmpeg 使用低延迟 H.264、无 B 帧和周期关键帧；管道写入阻塞由超时监视解除，编码器重启有次数上限。退出时先终止编码进程、必要时强制结束并回收，再等待写线程退出，避免满管道死锁。编码故障记录为显示故障，不触发任务 ABORT 或下发飞行命令。

收尾先停止视频生产，完成感知尾帧和 OCR 排空并抽取业务结果，再停止发布器和记录器，最后释放飞控线程。开启或关闭 QGC 显示都复用相同的任务生命周期。

配置字段见 [手册参数表](handbook.md#416a-qgcvideoconfig--qgc-视频发布)。离线单测覆盖同帧几何、观察旁路、乱序 OCR、有界显示缓存、阶段切换和编码器异常。`stream` 用例使用独立本地端口实测 RTP/MPEG-TS 编解码与晚接收；这不替代实际 QGC 窗口显示、现场网络延迟和飞行验证。
