# 统一任务运行

在线任务只有两种环境，入口均为 `python -m airdrop.run mission`：`--mode real` 使用真实链路，`--mode sitl` 使用仿真场景。二者复用组件装配、任务状态机、感知和记录流程。`replay` 是读取飞行目录的离线分析命令，不控制飞机。

## 阶段选择

| 参数 | 含义 |
| --- | --- |
| `--mission-control` / `--no-mission-control` | 是否运行任务控制；关闭后仅运行所选数据组件 |
| `--capture` / `--no-capture` | 是否接收视频 |
| `--record` / `--no-record` | 是否保存标准飞行目录；关闭不影响识别 |
| `--recognize` / `--no-recognize` | 是否执行检测、读数、坐标解算和目标统计 |
| `--drop-stage` / `--no-drop-stage` | 侦查处理完成后是否执行飞掠投放阶段 |
| `--real-release` / `--no-real-release` | 是否执行真实挂架动作；默认关闭 |
| `--auto-recon` / `--no-auto-recon` | 侦查航线由程序上传并启动，还是由操作手负责 |
| `--auto-land` / `--no-auto-land` | 投放阶段后是否执行自动降落尾段 |
| `--max-seconds` | 被动采集模式的时长上限；任务控制启用时使用各状态超时，不能混用该选项 |

接收视频、识别和落盘互相独立：关闭落盘仍可实时识别，关闭识别仍可保存视频与遥测，关闭视频仍可保存遥测。识别要求接收视频；只采集不加载识别模型或相机标定。参数组合不合法时，在连接飞控和创建运行文件之前拒绝。

任务控制开启时，起飞前视频仍更新实时预览与预检所读的最新帧，但不进入对齐缓冲，因此不会被感知或记录器保存；`airborne` / `airborne_skipped` 事件后才接收更新帧。进入 `ABORT` 或 `DONE` 后停止接收新帧，已接纳的在途帧仍按正常收尾流程完成。关闭任务控制的被动采集和离线回放仍从启动时接收帧。

启用识别时，会话在启动视频源前加载 YOLO，并按 `perception.opencv_threads` 设置主进程 OpenCV 线程数（默认 4），再按配置的视频输出宽高执行一次 YOLO 预热；已知相机标定尺寸必须与输出尺寸一致，加载、线程设置或预热失败都会中止启动。随后感知工作器启动 OCR 子进程并等待其真实 pipeline 预热完成。离线回放在启动工作器前使用相同线程设置。该设置不传入 OCR 子进程；关闭识别时不会创建模型，也不会更改 OpenCV 线程数。

真实环境默认由操作手上传并启动侦查，程序不会自动解锁。SITL 的自动操作手步骤只用于已选择的仿真任务控制；关闭自动侦查上传后，适配器也不能代替操作手上传。`--real-release` 只允许真实环境、任务控制和投放阶段同时开启；关闭实投时仍可运行真实弹道判据、航线与模拟动作记录，不等价于跳过投放阶段。

```bash
# 在线真实任务，默认模拟挂架动作
python -m airdrop.run mission --mode real
# 仿真任务使用同一状态机与处理组件
python -m airdrop.run mission --mode sitl
# 只采集标准飞行目录，不接管飞机、不载入识别模型
python -m airdrop.run mission --mode real --no-mission-control --capture --no-recognize --record --max-seconds 60
# 只侦查和处理，完成后盘旋，不规划投放阶段
python -m airdrop.run mission --mode real --no-drop-stage
# 飞掠投放阶段完成后飞出出口、盘旋退出，不上传降落项
python -m airdrop.run mission --mode real --no-auto-land
```

完整连接、航线、相机和输出选项以 `mission --help` 为准。真实任务的场地航线、备用点、飞掠航向/高度、地面高度和弹道参数由配置提供；不可将仿真世界的坐标当作真实场地数据。独立标定工具读取采集目录，输出相机文件供识别与坐标解算使用，字段约定见 [工具数据契约](tool_contracts.md)。

## 结束与完成含义

- 关闭任务控制：不构造任务控制器或状态机，不上传、启动、解锁、投弹、hold 或 RTL。正常结束、中断和异常退出均只收尾数据组件。
- 开启任务控制、关闭投放阶段：监视侦查，固定识别截止帧并排空，记录结果后盘旋完成，不规划备用点飞掠。
- 开启投放阶段、关闭识别：使用明确配置的备用点；缺少备用点应在启动前拒绝。
- 开启投放阶段、关闭自动降落：只上传飞掠段；判据触发后最多执行一次动作，继续飞到出口，任务完成后 hold 成功才进入 `DONE`。
- 开启自动降落：飞掠与降落尾段使用同一份已校验任务；关闭该选项时不读取降落文件，也不追加 LAND 项。

`DONE` 仅说明已选择的程序阶段完成。事件中的完成方式区分盘旋退出与降落任务完成；任务进度并不独立证明飞机已经落地。真实实投失败、任务上传失败、无法确认启动或必须执行的 hold 失败，均保留显式失败语义。

## 装配、传输与收尾

运行参数、组件构建与会话收尾分别位于 `airdrop/runtime/` 的独立模块；外部资源通过组件工厂注入。测试替换遥测、视频等 I/O 边界，仍执行真实协调器和状态机。

任务上传与回读、激活在后台顺序执行，主循环继续检查链路和输入健康。启动需要观察到任务模式；任务完成需要真实的未完成到完成变化，未知或查询失败不能充当未完成证据。回读核验任务数量、命令、位置、坐标系、参数和继续标志，容许传输中的合理浮点量化。

停止请求只禁止尚未开始的后续步骤，不证明远端已撤销。会话关闭等待在途命令及恢复动作真正收尾，然后才停止 MAVSDK。命令超时的结果未知锁存与连接内 raw 传输锁仍然有效。

收尾先停止视频生产，再通过感知工作线程的排空接口确认完整帧和 OCR 请求已处理，最后停感知并抽取剩余结果。记录器在必要事件写入后停止；SITL 参数尽力恢复，报告在遥测历史被清空前生成。每项清理独立尝试，前一项失败不能跳过后续资源释放；未排空或清理失败必须体现在结果中。

离线回放复用对齐和感知装配，保留播放终态、尾帧排空和严格失败返回码。SITL 的 manifest、精度报告与仿真资产初始化见 [仿真说明](simulation_world.md)；离线回归不代表真实飞行验收。

## QGC 显示

`mission` 与 `replay` 的 `--qgc-video` 可选启用只读合成视频；默认关闭。显示不改变采集、识别、记录、投放或降落阶段。`--qgc-host`、`--qgc-port`、`--qgc-transport` 指定接收端，默认 RTP/H.264 发送到 `127.0.0.1:5602`，与 SITL 输入端口分开。开启显示且关闭识别时只显示实时视频和状态，不载入相机或识别模型。完整说明见 [QGC 视频](qgc_video.md)。
